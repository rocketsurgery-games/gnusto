▸ 2026-07-14T21:48:25Z
DESIGN CHANGE (supersedes the earlier 'track the transitive precondition closure of refs' plan). Attack defect B via a REGION QUOTIENT rather than by tracking more concrete refs.

Insight (from the requires slice + user): player movement is not special. It is one instance of a REVERSIBLE, LOCAL state operator. Quotient the state space by the equivalence generated by such operators; keep only IRREVERSIBLE operators as real transitions. This collapses the wandering-around explosion by construction.

First instance to build: gated ROOM-GRAPH reachability core (shared primitive), reused three ways -- requires/depgraph (backward: dominating-gate min-cut to a target room), map connectivity (forward: flood-fill from here), and the explorer's location abstraction (this yak).

Soundness conditions (must all hold; err toward classifying an operator as irreversible when unsure):
1. Reversibility -> collapse only STRONGLY-CONNECTED components; one-way exits (chasm, trap-door slam) stay real transitions between regions.
2. No per-move side effects -> exits with :on-enter mutations are not free; stay real.
3. Darkness/hazards -> reachability carries a light bit (a lit lightable in inventory as a gate); dark rooms are lethal without light.
4. Gate-dependence -> the SCC/region structure is PARAMETERIZED by the barrier-state vector; recompute when a gate flips (opening the grating merges regions). Static regions = unsound.

Generalization (tracked in the new design doc + gnusto-zbg cross-ref): the same quotient applies to any reversible+independent operator (object placement among reachable containers, door open/close, NPC positioning), subject to state-dependent reversibility and independence (NB: Zork inventory limit breaks take-independence). This is the model-checking toolkit -- partial-order reduction, bisimulation quotient, symmetry reduction, abstraction refinement. Full generality is out of scope for B; build the room core with interfaces that allow later extension, and document the theory. See docs/design/reachability-quotient.md.

KEY EMPIRICAL FINDING on Zork (predicted by design-doc conditions 1/2/4): pure STATIC topology is an unsound input for the backward query. Zork's 110-room / 315-edge map collapses to a SINGLE all-open SCC, and required_barriers under-reports badly (returns [] for @kitchen, @cellar, @gallery; only finds @cyclops). Cause: the map is full of DYNAMICALLY ASYMMETRIC links declared as ordinary bidirectional exits -- the trap-door slams shut on descent, the grate only unlocks from below, the chimney/river are one-way -- so spurious reverse edges create cycles that route the cut test AROUND physically-unavoidable barriers (even the kitchen window you must open to enter). Forward reachable_rooms (over-approx) is unaffected and stays sound for deadend claims.

CONSEQUENCE: to be rigorously sound for backward required-barriers AND for the region quotient, the movement model must carry DIRECTIONAL / gate-state honesty, not naive static exits. Two candidate fixes to decide with the user: (A) game-authoritative annotation of one-way/asymmetric exits (drop the spurious free reverse edge; model return via the gate) -- fits the deterministic/explicit philosophy; or (B) derive directional traversability from initial gate state + barrier :through side + room :on-enter slam analysis (monotone forward reachability treating barrier-opening as progress).
